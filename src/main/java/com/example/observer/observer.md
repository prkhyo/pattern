# 옵저버 패턴(Observer Pattern)

----


## 옵저버 패턴이란?
<blockquote> 
<p>옵저버 패턴은 관칠자들이 관찰하고 있는 관찰 대상(Subject) 객체의 상태 변화가 발생할 때, 이를 구독하고 있는 관찰자(Observer)들에게 자동으로 통지하고, 관찰자들은 알림을 받아 조치를 취하는 행동 패턴이다. </p> 
Pub/Sub(발행/구독) 모델로도 알려져 있으며, 이벤트 기반 시스템이나 상태 변화 감시 시스템에서 자주 활용된다.
<br>
→ 유투브 채널 발행자, 구독자 관계와 유사 (발행자는 관찰 대상, 구독자는 옵저버의 역할)

</blockquote> 
<br>


### ➤ 옵저버 패턴의 구조 <br>

<table class="table">
<tbody>
<tr>
<td><strong>Subject (주체 인터페이스)</strong></td>
<td>관찰 대상을 정의하고, 관찰자를 등록/해제하는 메서드를 제공한다.
</tr>
<tr>
<td><strong>ConcreteSubject (주체 구현체)</strong></td>
<td>실제로 상태를 변경하고 관찰자에게 알림을 발송하는 객체이다. 내부에 옵저버 리스트를 유지하며, 상태 변경 시 모든 옵저버에게 통지한다.</td>
</tr>
<tr>
<td><strong>Observer (옵저버 인터페이스)</strong></td>
<td>관찰자들을 묶는 공통 인터페이스. 관찰자들의 기본 동작을 정의한다.</td>
</tr>
<tr>
<td><strong>ConcreteObserver (옵저버 구현체)</strong></td>
<td>실제로 관찰 대상의 상태 변경에 반응하는 구체적인 옵저버 구현체이다.</td>
</tr>
</tbody>
</table> <br><br>

### ➤ 옵저버 패턴의 구조상 다른 디자인 패턴과 다른 점? <br>
- 옵저버 패턴은 상호작용할 합성객체를 내부에 리스트로 관리한다.<br>
- 일대다(one-to-many) 의존성을 가진다.

<br><br><br>
***




##  옵저버 패턴의 흐름 <br>

1. 여러 개의 옵저버가 하나의 주체에 연결된다.
2. 주체의 상태가 변경되면, notify 메서드를 통해 모든 옵저버에게 알림을 보낸다.
3. 알림을 통보를 받은 옵저버들은 상태를 업데이트하거나 알림을 처리한다.
4. 옵저버들은 언제든지 주체의 옵저버 리스트에서 추가/삭제될 수 있다.



<br><br><br>



***



## 장점과 단점<br>


### ➤ 장점
- 주체와 옵저버는 서로 독립적이며, 각자 변경이 되어도 다른 클래스에 영향을 미치지 않는다. (느슨한 결합)
- 새로운 옵저버를 쉽게 추가할 수 있다. 주체의 코드를 수정하지 않고도 다양한 타입의 옵저버를 연결할 수 있다. (확장성)
- 주체의 상태가 변할 때 옵저버가 자동으로 업데이트되기때문에 상태 동기화가 편리하다.


### ➤ 단점
- 옵저버가 많아지면 복잡성이 증가하고, 상태 변경에 따른 알림이 많아질 경우 성능 저하가 발생할 수 있다.
- 옵저버 등록을 해제하지 않으면 메모리 누수가 발생할 수 있으며, 이는 프로그램의 성능 저하로 이어질 수 있다.
